### Model Internals That Need Fixes

- Extension profile cannot be validated: Vocabulary entry names shall not match a top-level JSON-LD context term.
  - [Issue #1477](https://github.com/spdx/spdx-3-model/issues/1477)
  - There are JSON-LD context issues with these vocabulary entries:
    - `Core/ProfileIdentifierType/extension`
    - `Core/RelationshipType/createdBy`
    - `Core/ExternalIdentifierType/requirementUID`
  - With standard JSON-LD libraries, these are resolved as Core properties:
    - `Core/extension`
    - `Core/createdBy`
    - `Core/requirementUID`
  - SPDX 3 documents with `extension` as a value in `profileConformance` will fail validation using those libraries because `Core/extension` cannot be a value for `profileConformance`. The Extension profile will not work.

- "Foundation individuals" `CreationInfo` must remain immutable.
  - [Issue #1465](https://github.com/spdx/spdx-3-model/issues/1465)
  - Proposed resolution:
    - Metadata maintained on the model side: [PR #1484](https://github.com/spdx/spdx-3-model/pull/1484)
    - `spec-parser` honors the metadata without hardcoding: [PR #219](https://github.com/spdx/spec-parser/pull/219)
    - The proposal preserves SPDX 3.0.1 individual IRIs for compatibility.
