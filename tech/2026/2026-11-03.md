- Model internals that need fixes
  - Extension profile cannot be validated — Vocabulary entry names shall not match a top-level JSON-LD context term [#1477](https://github.com/spdx/spdx-3-model/issues/1477)
    - There are JSON-LD context issues with these vocab entries:
      - `Core/ProfileIdentifierType/extension`
      - `Core/RelationshipType/createdBy`
      - `Core/ExternalIdentifierType/requirementUID`
    - With standard JSON-LD libraries, they are all resolved as Core properties:
      - `Core/extension`
      - `Core/createdBy`
      - `Core/requirementUID`
    - SPDX 3 document with `extension` as a value in `profileConformance` will fail validation when using those libraries (as `Core/extension` cannot be a value for `profileConformance`) → Extension will not work.
  - "Foundation individuals" from same spec version must share the same immutable `CreationInfo` [#1465](https://github.com/spdx/spdx-3-model/issues/1465)
