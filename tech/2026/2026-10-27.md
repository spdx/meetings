- Vocabulary entry names shall not match a top-level JSON-LD context term
  - [Issue #1477](https://github.com/spdx/spdx-3-model/issues/1477)
  - JSON-LD context issues exist with the following vocabulary entries:
    - `Core/ProfileIdentifierType/extension`
    - `Core/RelationshipType/createdBy`
    - `Core/ExternalIdentifierType/requirementUID`
  - Standard JSON-LD libraries resolve these entries as Core properties:
    - `Core/extension`
    - `Core/createdBy`
    - `Core/requirementUID`
  - An SPDX 3 document with `extension` as a value in `profileConformance` will fail validation when using these libraries because `Core/extension` cannot be a value for `profileConformance`. Consequently, the extension will not work.

### Internationalization - Issue #1340

- The default language should be explicitly defined, likely as English.
- Discussion addressed how multiple languages should be represented.
  - Language designation may need to be applied at the element level.
  - An `isTranslationOf` relationship may be required.
  - Bob referenced another standard that uses multilingual strings.
  - `inLanguage` is an element property.
- Discussion favored using one language per element for SPDX 3.0, with broader internationalization considerations revisited for SPDX 4.0.
