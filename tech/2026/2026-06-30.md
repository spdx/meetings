### Microsoft Feedback on SPDX 3.1

Microsoft provided feedback on SPDX 3.1 implementation considerations.

#### Profile Support and Implementation Guidance

- Partial support for profiles was discussed. Microsoft would like more guidance in this area, including tooling support to declare which profiles are supported.
- “Supported” was discussed as meaning conformance to the mandatory fields for a profile.
- “Unsupported” was discussed as meaning fields may be used without full support for the applicable conformance points.
- Microsoft noted that suppliers may provide SBOMs outside the scope of software and asked what tooling should do in those cases, including whether to parse and preserve the information.
- The size of the Windows ecosystem requires handling multiple suppliers at multiple stages of conformance.
- Implementation guidance needs to be further developed in the SPDX “using” repository: https://github.com/spdx/using
- The group discussed whether the specification should reference external implementation guidance by linking to this material.

#### `publishedTime` and Examples

- `publishedTime` in 3.1 was identified as a breaking change that needs to be reverted.
- There was discussion about whether material was removed from Core and whether the Operations profile removed a number of items from Core.
- Art confirmed that the issue is with examples.
- The JSON snippet in SPDX 3.0 is incorrect: https://spdx.github.io/spdx-spec/v3.0.1/model/Security/Classes/VexAffectedVulnAssessmentRelationship/
- The issue is corrected in 3.1-dev, since RC1: https://spdx.github.io/spdx-spec/v3.1-dev/model/Security/Classes/VexAffectedVulnAssessmentRelationship/

#### Serialization

- Serialization-related actions need to go to the Serialization Working Group.
- ABNF is being defined twice and should be consolidated and harmonized. The related `.md` file should be reviewed.

#### Medium-Priority Feedback

- 4.1: Examples in new namespaces are on the radar.
- 4.2: PackageURL will be updated once it passes ECMA: https://github.com/spdx/spdx-spec/pull/1397
- 4.3: `responsibilityCategory` needs an editorial change. The relevant category is SupplyChain.
- 4.4: Very large documents, including documents with more than 100,000 elements, need implementation guidance on splitting and processing.
  - Art noted the streaming use case.
  - Key ordering issue: https://github.com/spdx/spdx-spec/issues/1339
  - JSONL issue: https://github.com/spdx/spdx-spec/issues/1410
  - Implementation ideas are welcome in the issues. The Golang team has already raised related concerns.
- 4.5: It was suggested that strength should be updated to include SHA-256 in addition to SHA-1.
  - SHA-512 was discussed for CRA.
  - BSI TR-03183 requires SHA-512, so the group discussed adding related material to the specification and citing BSI TR-03183.
- 4.6: Additional reference examples were requested. Yocto, Linux, and Zephyr were suggested.

#### Backward Compatibility and Migration

- 5.1: Backward compatibility was discussed, including changing the way future IRIs are handled to improve compatibility.
  - Starting with 3.1, `sameAs` will be used to reference back.
  - A 3.1 parser cannot parse 3.0.
  - SPDX 3.0.1 can be converted via `sed` to be parsed with 3.1.
  - The conformance phrase needs to be reworded.
  - SPDX is semantically versioned, with one exception: 3.0.1.
- 5.2: Implementation guidance is needed to help users migrate from 2.x and 3.0.1 to 3.1.
  - Migration guidance from 2.x to 3.0.1 exists at: https://spdx.github.io/using/diffs-from-previous-editions/
  - Migration guidance from 3.0.1 to 3.1 does not yet exist.
  - Related source file: https://github.com/spdx/using/blob/main/docs/diffs-from-previous-editions.md
  - The group discussed referencing this material from the specification.
- 5.3: Issues should be raised for these items, and each should be explicitly resolved in Git.
  - The group requested one issue per bullet point.
- 5.5: AI and Dataset examples were discussed.
  - `AIPackage` wiring to `DatasetPackage` now has a few examples available for review, and additional examples are welcome: https://github.com/spdx/spdx-examples/pulls
  - Suggestions related to `Annotations.ttl` were noted in: https://github.com/spdx/spdx-spec/pull/1405
