## Notes

### SPDX 3.0 and SBOM Generation

* The group discussed introducing SPDX 3.0 support for Zephyr 2.2 and 2.3 and the Linux kernel `make spdx` implementation.
* The [SPDX 3 Visualization Tool](https://kartben.github.io/spdx3_viz/) is looking for AI BOM sample files.
* Work is ongoing by Kurokawa-san, a colleague of Ito, on a trial SBOM-generation environment for the Xen build toolchain.
* Ito and Kurokawa-san will discuss a strategy for integrating and maintaining the SBOM-generation Python scripts within the Xen toolchain.
* The current environment uses KernelSBOM, which has been merged into Linus's tree, as Kate noted.
* Several items may need to be patched to support Xen-specific relationships and configuration systems.
* The implementation remains under review because it was generated using Claude, and some portions may not yet provide sufficient functionality.
* SPDX 3.0 supports linkage between files and can include security information associated with CSAF, VEX, and related formats.
* No sufficiently clear VEX guidance for open source projects has been identified so far.

### SPDX AI

* The group discussed reference examples for AI and safety, including minimum information about training data.
* References:

  * [CBC: Anthropic AI copyright settlement](https://www.cbc.ca/news/business/anthropic-ai-copyright-settlement-1.7626707)

* Gopi demonstrated the [AIkaBoOM](https://github.com/rgopikrishnan91/aikaboom) tool, which mines GitHub, Hugging Face, and arXiv.

* The group discussed SPDX 3.1 Lite.
* Participants are examining SPDX 2.3-to-3.0 translations. Some relationships still need to be checked.
* Additional discussion is planned.
